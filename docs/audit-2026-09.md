## 1. Executive summary

### Launch-readiness verdict: **NOT READY. The engineering foundation is strong; content facts, one security patch, forms and domain work block launch.**

What is solid, verified live:
- **The pre-launch lock is consistent everywhere.** 269/269 Capriowear pages plus the parent site, Gear, /studio, /styleguide and every 404 carry `noindex, nofollow`. robots.txt is exactly `User-Agent: *` / `Disallow: /`. /sitemap.xml is an empty urlset. 0 occurrences of `vercel.app` or `localhost` in any HTML or JSON-LD. Every canonical and og:url is `https://www.capriosports.com` + the page's own path.
- **The draft guard works for drafts.** All 233 draft product pages emit BreadcrumbList only, no Product or FAQPage.
- 34/34 FAQPage blocks match the visible FAQ text exactly. Titles, descriptions and H1s are unique, one H1 per page, no skipped heading levels.
- All internal links resolve 200 with no redirect chains, and there are no orphan pages. No pill falls back to a list page when a product page exists (except the 3 Joggers card-only styles, which are by design).
- The gender toggle works on all 9 gendered list pages (clicked in Chromium at 1440 and 390 px; counts, `aria-pressed`, Enter/Space all correct).
- Teamwear templates are nearly perfect: 68 product pages and 10 list pages match the template, with 2 exceptions (one of them documented).
- Performance is excellent: Lighthouse Performance 96 to 100, CLS 0 to 0.07, TBT 0 to 10 ms, about 190 KB gz First Load JS. `tsc` and `eslint` are clean with 0 `any`. No secrets in the repo, git history or client bundles.

### 3b. Claims risk and the GSP+ / REX research

Every claim below needs a current certificate or document on file before launch: ISO 9001, ISO 45001, ISO 14001 (verifiable on IAF CertSearch, scope covering apparel at the Sialkot site); the amfori BSCI audit report (an audit rating, not a certificate); SGS test reports (and SGS's permission to show its logo); IMAC coverage of the apparel unit; WFSGI membership; the AQL/QC procedure; "No child labor" (usually evidenced by the BSCI report); client-logo permissions (confirmed 2026-08-24; check they are apparel clients, not Gear); the 80+/100,000+/75,000/700+ figures; test evidence for the LST "UPF 50+" and "blood flow" copy.

**GSP+ Form A (EU): replaced by REX.**
- TDAP: "Pakistan completely switched to the REX system of the EU on December 31, 2017. Effective January 1, 2018 TDAP stopped issuing Certificate of Origin/ Form-A for exports to the EU-27, Switzerland, Norway and UK." Only REX-registered exporters may issue a "statement on origin". https://tdap.gov.pk/origin-certification-by-tdap/ ; https://tdap.gov.pk/wp-content/uploads/2026/02/7-REX_Operational_Guide_V3_Dec-2023.pdf
- DG TAXUD: "the REX system is the only system applicable to certify the origin of goods in the GSP"; beneficiary authorities "may not issue certificates of origin Form A anymore" (from 1 Jan 2021). https://taxation-customs.ec.europa.eu/news/generalized-system-preferences-application-rex-system-2021-01-11_en ; https://taxation-customs.ec.europa.eu/online-services/online-services-and-databases-customs/registered-exporter-rex-system_en . Legal basis: Implementing Regulation (EU) 2015/2447, REX provisions. (The EUR 6,000 non-registered threshold should be checked on EUR-Lex.)

**UK (DCTS).** GOV.UK accepts "a Form A, which does not need to be stamped or signed by an authority" or "an origin declaration on an invoice, packing list or consignment note" (https://www.gov.uk/guidance/use-the-developing-countries-trading-scheme-to-import-goods). TDAP: exporters "self-certify their export consignments on Form-A" (https://tdap.gov.pk/wp-content/uploads/2026/02/13.-UK-DCTS_Rev-7.pdf). So "Form A" is still meaningful for the UK, as a self-certified form, but not for the EU.

**"0% EU duty".** Non-LDC GSP+ apparel (HS 61/62) must be "manufactured from yarn" (double transformation). Garments cut from fabric imported from outside the cumulation zone pay the MFN rate (commonly 12% on apparel). The site offers fabric "sourced or matched to your reference", so some orders will not qualify. GSP Regulation 978/2012 is extended to 31 Dec 2027 (Reg. 2023/2663); press reports say Pakistan must reapply under the new regulation (secondary source, verify on EUR-Lex). Under DDP the duty is Caprio's landed-cost item, not a buyer-side guarantee. Sources: EU Annex 22-03 of 2015/2446; TDAP origin guide https://tdap.gov.pk/wp-content/uploads/2024/01/4-Origin-Criteria-and-Rules-of-Origin-3.pdf ; https://trade.ec.europa.eu/access-to-markets/pt/news/eu-scheme-generalised-tariff-preferences-gsp-extended-until-31-december-2027

**Document `styleMedia` (one per style):**
- `division` (activewear, teamwear, lifting-gears, boxing-and-mma), required.
- `category` slug, required. `style` slug, required, unique per division + category (async check).
- `sku`, required, `^CAP-[A-Z]{3}-\d{2}$`; must match the TS card.
- `productName`: the exact card name; no en/em dash.
- `approved` (boolean, default false): "final product photography". QA or test shots stay false and can never publish a page.
- `images[]`: image with `hotspot: true` and `lqip` + `dimensions` metadata; max 9; at least 1 when approved; each at least 1200 px wide. Per image: `alt` (required, must contain `productName`, no dash), optional `view` (front, back, side, detail, on-model, flat-lay) and `color` (for per-colorway images if needed).
- Ordering: `images[0]` = card image, gallery lead and Product schema image; `images[1]` = card hover swap (ProductCardMedia).

```ts
// sanity/schemas/documents/styleMedia.ts
import { defineArrayMember, defineField, defineType } from "sanity";
const DASH = /[–—]/; const SLUG = /^[a-z0-9-]+$/;
export default defineType({
  name: "styleMedia", title: "Style images", type: "document",
  fields: [
    defineField({ name: "division", type: "string", options: { list: ["activewear", "teamwear", "lifting-gears", "boxing-and-mma"] }, validation: (r) => r.required() }),
    defineField({ name: "category", type: "string", validation: (r) => r.required().regex(SLUG) }),
    defineField({ name: "style", type: "string", description: "Style slug exactly as in content/*.ts",
      validation: (r) => r.required().regex(SLUG).custom(async (style, ctx) => {
        const d = ctx.document as { _id: string; division?: string; category?: string };
        const id = d._id.replace(/^drafts\./, "");
        const n = await ctx.getClient({ apiVersion: "2025-01-01" }).fetch<number>(
          `count(*[_type=="styleMedia" && division==$d && category==$c && style==$s && !(_id in [$id,"drafts."+$id])])`,
          { d: d.division, c: d.category, s: style, id });
        return n === 0 || "Another styleMedia document already covers this style";
      }) }),
    defineField({ name: "sku", type: "string", validation: (r) => r.required().regex(/^CAP-[A-Z]{3}-\d{2}$/, { name: "CAP-XXX-00" }) }),
    defineField({ name: "productName", type: "string", validation: (r) => r.required().custom((v) => !v || !DASH.test(v) || "No en or em dashes") }),
    defineField({ name: "approved", title: "Approved product photography", type: "boolean", initialValue: false }),
    defineField({ name: "images", type: "array",
      of: [defineArrayMember({ type: "image", options: { hotspot: true, metadata: ["lqip", "dimensions"] },
        fields: [
          defineField({ name: "alt", type: "string", validation: (r) => r.required().custom((alt, ctx) => {
            const name = (ctx.document as { productName?: string })?.productName;
            if (!alt) return "Alt text is required";
            if (DASH.test(alt)) return "No en or em dashes";
            if (name && !alt.toLowerCase().includes(name.toLowerCase())) return `Alt must contain "${name}"`;
            return true; }) }),
          defineField({ name: "view", type: "string", options: { list: ["front", "back", "side", "detail", "on-model", "flat-lay"] } }),
          defineField({ name: "color", type: "string" }),
        ],
        validation: (r) => r.custom((img) => {
          const ref = (img as { asset?: { _ref?: string } } | undefined)?.asset?._ref;
          if (!ref) return "Upload an image";
          return Number(ref.split("-")[2]?.split("x")[0]) >= 1200 || "At least 1200px wide";
        }) })],
      validation: (r) => r.max(9).custom((imgs, ctx) =>
        (ctx.document as { approved?: boolean })?.approved && !(imgs as unknown[] | undefined)?.length ? "Approved style needs an image" : true) }),
  ],
  preview: { select: { title: "productName", subtitle: "sku", media: "images.0" } },
});
```

// lib/sanity/fetch.ts
import "server-only";
import { createClient } from "next-sanity";
import { apiVersion, dataset, projectId } from "@/sanity/env";
const client = createClient({ projectId, dataset, apiVersion, useCdn: false, perspective: "published" });
export const STYLE_MEDIA_TAG = "styleMedia";
const Q = /* groq */ `*[_type=="styleMedia" && approved==true]{
  division, category, style, sku, productName,
  "images": images[defined(asset._ref)]{ alt, view, color, hotspot, "url": asset->url,
    "w": asset->metadata.dimensions.width, "h": asset->metadata.dimensions.height, "lqip": asset->metadata.lqip } }`;
export async function getStyleMediaIndex() {
  const docs = await client.fetch<StyleMedia[]>(Q, {}, { cache: "force-cache", next: { tags: [STYLE_MEDIA_TAG] } });
  return new Map(docs.map((d) => [`${d.division}/${d.category}/${d.style}`, d]));
}

**Signed revalidation webhook:**
```ts
// app/api/revalidate/sanity/route.ts
import { revalidateTag } from "next/cache";
import type { NextRequest } from "next/server";
import { parseBody } from "next-sanity/webhook";
import { STYLE_MEDIA_TAG } from "@/lib/sanity/fetch";
export async function POST(req: NextRequest) {
  const secret = process.env.SANITY_REVALIDATE_SECRET;
  if (!secret) return new Response("Not configured", { status: 500 });
  const { isValidSignature, body } = await parseBody<{ _type?: string }>(req, secret);
  if (!isValidSignature) return new Response("Invalid signature", { status: 401 });
  if (body?._type !== "styleMedia") return Response.json({ skipped: true });
  revalidateTag(STYLE_MEDIA_TAG, "max"); // Next 16 two-argument form; use { expire: 0 } for an immediate flip
  return Response.json({ revalidated: STYLE_MEDIA_TAG });
}
```
Webhook: filter `_type=="styleMedia"`, projection `{_type,division,category,style}`, secret in Vercel (Sensitive, Production).

### Publish flow

1. An editor uploads photos to a `styleMedia` doc and ticks **approved**.
2. The webhook fires; the `styleMedia` tag goes stale.
3. On the next request the product page re-renders with the Sanity image. If the TS card is `status: "published"`, readiness passes, so the page becomes indexable (once indexing is on), joins the sitemap and the list-page ItemList, and gains Product + FAQPage schema. The sitemap and ItemList read the same tagged fetch.

**Can a placeholder publish?** Today, yes: a QA shot did (A1-01), because `isRealImageSrc()` is a blocklist (E-02). With the allowlist + `approved` flag, a page publishes only from an approved Sanity doc with alt text containing the product name. Failure cases stay safe: unapproving, deleting the image or a Sanity outage at build time all fall back to draft behaviour (noindex, BreadcrumbList only). `assertPublishedStylesReady` still guards TS statuses at build; at runtime `isPublished()`'s draft fallback is the guard. Adding a brand-new style stays a TS change plus a deploy (product routes use `dynamicParams = false`).
